# 따릉이 배포 파일의 소스 세대 (R2 #18, T4 #16)

서울 열린데이터광장 OA-15249 배포 파일이다. **API가 아니라 파일로 받았다.**

## 왜 API를 쓰지 않는가

API(`tbCycleRentUseMonthInfo`)는 `LIST_TOTAL_COUNT`로 93,187건을 보고하면서
`list_all`이 약 30,000건에서 멈춘다. 창을 끝까지 훑으면 전수를 받을 수 있음을
확인했으므로(202412: 93,187/93,187, 27.7분) 서버 제한이 아니라 클라이언트 정지
조건의 결함이다. 그러나 한 달에 28분이면 60개월이 비현실적이고, 배포 파일이 같은
기간을 전수로 준다.

이전 스냅샷이 전수의 **31.9%**(29,775/93,187)였다는 점이 중요하다. 응답이
`권종 → 성별 → 연령대 → 대여소` 순으로 정렬돼 있어 잘림이 무작위가 아니라 **범주
단위로** 일어났다 — 60개월 중 39개월에 남성이 전혀 없고 54개월이 정기권만 남았다.
공공데이터 API가 전수를 보고하면서 전수를 주지 않고, 그 누락이 편향된다는 사례로
서론과 Threats에 쓴다.

파일 35개, 총 4,935,022행.

## 역할

| | 기간 | T4 (#16) | R2 (#18) |
|---|---|---|---|
| G1 | 2020-01~2020-05 | ✅ | ✅ |
| G2 | 2020-06~2022-12 (2021-09 제외) | ✅ | ✅ |
| I1 | 2021-09 | ✅ | ✅ 일시적 파손 사례 |
| G3 | 2023-01~2023-12 | ✅ | ✅ |
| G4 | 2024-01~2024-12 | ❌ | ✅ **semantic break** |

**T4 = G1+G2+I1+G3, 2020-01~2023-12 (48개월).** 이 넷은 같은 것을 다르게 적은
것이라 고정된 계약으로 흡수할 수 있다.

**G4는 T4에서 제외한다.** 인구통계 차원이 사라지고 `이용건수`가 `대여건수`/
`반납건수`로 갈렸다. 2023-12와 2024-01 사이에 겹치는 기간이 없어 두 양이 같은
것인지 검증할 수 없다. 시계열 중간에 정의가 바뀌는 지점을 둘 수 없다.

**G4를 성공시키려고 계약을 확장하지 않는다.** 표현이 아니라 의미가 바뀐 소스는
고정 계약이 fail-closed 하는 것이 옳은 결과이고, 그것이 R2가 재려는 경계다.

**I1은 새 세대가 아니라 incident다.** 한 달 뒤 원복되므로 영구적 진화와 구분해
따로 평가한다.

## 인코딩은 R2의 평가 대상이 아니다

파일마다 인코딩이 다르고 G2 안에서도 섞인다(cp949 20개 + utf-8-sig 5개). 세대마다
`SourceRef.encoding`을 바꾸면 BuildSpec이 달라져 R2의 same-pipeline 전제가 깨지고,
단일 선언으로는 G2 내부 혼재를 표현할 수도 없다.

그래서 **decode는 고정 파이프라인 바깥의 ingest 단계**에서 한다. 원본 바이트는
그대로 보존하고, 파일별 인코딩과 SHA-256을 `ingest_manifest.json`에 기록해 스냅샷
안에 함께 넣는다. 인코딩 변화는 관찰된 source evolution으로 여기 남지만, R2가
직접 평가하는 것은 **decode 이후의 스키마·값 표현 진화에 대한 계약 안정성**이다.

## 세대

**세대 경계가 연도와 일치하지 않는다.** 2020년 안에서 한 번(20.05 → 20.06),
2021년에 한 달짜리 incident가 한 번 일어난다. R2 스냅샷을 연도로 자르면 한 스냅샷
안에 두 표현이 섞여 세대 *간* 변화가 아니라 세대 *내* 혼재를 재게 된다.

**G2는 쪼개지 않는다.** 내부에 `2022-01`과 `202207`이 섞여 있는데, 그것까지 하나의
고정 계약이 견디는지가 R2가 물어야 할 현실적인 변동이다. 쪼개면 어려운 경우를
피해서 소스를 정리해 준 셈이 된다.

## 세대 사이에 바뀐 것

| | G1 | G2 | I1 | G3 | G4 |
|---|---|---|---|---|---|
| 시점 컬럼 | `대여일자` | `대여일자` | `대여일자` | **`대여년월`** | **`기준년월`** |
| 시점 형식 | `2020-01` | `2020-06`·`202207` 혼재 | `2021-09` | **`202301`** | `202401` |
| 거리 | `이동거리` | `이동거리(M)` | **`이용거리(M)`** | `이용거리(M)` | 없음 |
| 시간 | `이용시간` | `이용시간(분)` | **`이용시간(본)`** | `이용시간(분)` | 없음 |
| 대여소번호 | `3`·`00003` 혼재 | `00003`·`102` 혼재 | `00003` | `102` | **없음** |
| 연령대 | `AGE_003` | `AGE_003`→`~10대` | `AGE_003` | `~10대` | 없음 |
| 성별 결측 | `\N` | `\N` | `\N` | 없음 | 없음 |
| 단위 | 대여소×권종×성별×연령×월 | 같음 | 같음 | 같음 | **대여소×월** |

고정 계약이 흡수해야 할 것과 남길 것을 가른다.

| 차이 | 처리 |
|---|---|
| `\N` → null | `null_tokens`. **성별만이 아니라 운동량·탄소량에도 있다**(각 229건) |
| 세대별 헤더 → 하나의 컬럼 | alias/coalesce **신규** |
| `3` ↔ `00003` | zfill **신규** — T4의 식별자라 필수 |
| `YYYY-MM` ↔ `YYYYMM` | 다중 형식 월 파서 **신규** |
| `AGE_003` ↔ `~10대` | **매핑하지 않는다** — 근거가 배포 파일에 없고, T4는 쓰지 않는다 |
| `F`/`f`/`M`/`m` | **고치지 않는다** — T4는 쓰지 않는다 |

마지막 둘은 계약 경계로 남긴다. 근거 없는 값 매핑은 정규화가 아니라 조작이고,
**Silver 계약이 선언한 것만 보장한다**는 서술과 일관된다.
